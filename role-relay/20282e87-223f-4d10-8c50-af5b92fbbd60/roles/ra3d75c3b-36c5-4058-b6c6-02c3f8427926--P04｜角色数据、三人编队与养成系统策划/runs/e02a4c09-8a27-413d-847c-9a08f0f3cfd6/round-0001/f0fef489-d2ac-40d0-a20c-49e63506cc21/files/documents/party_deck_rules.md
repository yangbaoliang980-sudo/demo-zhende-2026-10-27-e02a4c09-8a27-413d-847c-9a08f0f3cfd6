# P03｜三人队伍卡组构筑与牌区语义（隔离测试草案）

版本：`P03-DECK-0.1.0-MOCK`；任务：`TASK-P03-S01-S02-LOCAL-001`；证据：**P03_LOCAL_STATIC_ONLY**。本文件与对应 JSON 均不是已签字的 P15 DeckPatch 或 P13 DTO，不实现抽牌、洗牌、费用扣减、BattleState 写入。

## 1. 前置决策与受限角色

- 产品只确认同时上阵三人；初始实际拥有多少角色、牌数量、怪/Boss数量仍为 P01 `DEC-004`，不能由这里的测试样例决定。
- `MOCK_P03_CHAR_A/B/C/D` 是4个**纯测试角色槽标识**，用于枚举三人阵容及校验专属牌差异，不是4个已批准的真实角色。P04 必须给出正式角色ID、定位和角色合法性，P22 负责唯一ID及所有引用。
- 本版仅在四个 mock 槽组成的测试集合内定义合法三人排列，即4P3=24个有序样例；不宣称已覆盖未知真实角色图鉴。**只允许作为 fixture 输入**。
- 初始战斗资源由批准政策或 mock fixture 注入；未定义无学习日是否允许免费基础卡或能量。P01 `DEC-003` 仍待用户。

## 2. S01 / S02 明确内容边界

S01 定义三张基本牌：`STRIKE`（攻击）、`BARRIER`（护盾）、`RECOVER`（治疗）。S02 补 `EMBER`（持续伤害），形成四类活动样例：`ATTACK`、`DEFENSE`、`HEAL`、`STATUS(DOT)`；并给 A/B/C/D 四个测试角色槽分别提供一张专属牌。总计8个可静态验证的 MOCK 活动卡配置。

`FOCUS_DRAFT` / `FEEBLE_DRAFT` 是额外两张状态**结构提议样例**，它们的 BUFF / DEBUFF 时序、叠层和修正公式没有上游批准；`mock_playable=false`，不纳入实际构筑输入，不可宣称运行时合法。所有数值属于测试参数，均由 P05 校正后才能转为候选正式内容。

## 3. 构筑公式（只针对本轮 fixture）

输入：3 个非重复、已存在于 mock 槽表中的 `character_id`，以编队顺序提供。校验者还需判定实际队伍合法性（正式版本归 P04/P17）。

构筑：按以下写死的**测试配方**拼接牌模板：

| 模板 | fixture份数 | 类别 |
| --- | ---: | --- |
| `MOCK_P03_CARD_STRIKE` | 2 | 攻击 |
| `MOCK_P03_CARD_BARRIER` | 2 | 护盾 |
| `MOCK_P03_CARD_RECOVER` | 1 | 治疗 |
| `MOCK_P03_CARD_EMBER` | 1 | DOT |
| 3个所选槽位各自专属牌 | 各1 | 按不同槽位区分 |

生成9个各具有独立 `card_instance_id` 的可机读卡片引用；模板引用保持原 `card_id`。相同队伍不同排列只改变三个专属实例的位置，不改变模板多重集合。此规则只用于离线构筑枚举，不代表实际可获得、起始牌量、总牌量、角色解锁或发卡政策已经批准。配置和24种有序示例见 `../../content/cards/deck_build_fixtures.json`。

## 4. 牌区与手牌：约束但不写运行代码

- 卡模版 `card_id` 与每战斗单张 `card_instance_id` 是不同身份；必须由P13/P22确定正式编码规范，任何时刻每实例至多属于一处牌区。
- 已批准战斗语义的候选：`HAND → DISCARD` 发生在 P14 一次权威事务，先验证全部条件，再缓冲 `ENERGY_SPENT` 和 `CARD_MOVED`，拒绝命令无副作用。
- `draw` 数组左端为下一张；若 `draw` 为空而 `discard` 不空，可由已批准 P15 策略提出 recycle + deterministic shuffle 候选；`xorshift32-v1` + Fisher–Yates 是 P02 夹具提议、**P13/P15尚未签署**。
- 若 `draw/discard` 均空，不凭空补卡；缺牌只发生 `DRAW_SHORTFALL` 预期事件，不能擅加疲劳扣血。这是继承P02草案的技术语义，而非新规则。
- `HAND` 最高容量、回合初始抽牌数、剩余手牌是否回合弃置、未出牌保存策略、弃牌回流、能量恢复预算，全由P03/P05/P15经P01或接口owner确认后确定；本版**不写假定正式值**。测试场景自带冻结手牌和能量，不意味着游戏运行已有这些机制。
- 三人共同卡组、角色死亡时其所属卡是否可继续打出、重复状态叠层、零学习日启动资源均需正式评审。此 fixture 用“actor必须在mock队伍，专属牌只允许关联owner出牌”的**测试约束**；正式P15验证规则待P04/P13确认。

## 5. 至少两种有意义的同局合法动作

`content/cards/choice_scenarios.json` 的 `S-A` 在相同单局初始快照、相同2能量、同四张基础牌手牌下提供4个独立**互斥选择分支**：对带2盾敌人造成4点原始攻击（盾-2，血-2）；对仅有4/10生命的队友治疗5点（恢复到9）；给予4盾；或者施加下一次敌方 owner 回合入口待触发的2点DOT。分支间不得连做并冒充相同 revision 的完整战斗日志。

`S-B` 可单独比较相同队伍3张不同专属牌与费用；`S-C/S-D` 给出能量不足、目标无效、非手牌和未批准状态的反例。预期值只经P03内容静态审核，不是P15/P14实际运行。

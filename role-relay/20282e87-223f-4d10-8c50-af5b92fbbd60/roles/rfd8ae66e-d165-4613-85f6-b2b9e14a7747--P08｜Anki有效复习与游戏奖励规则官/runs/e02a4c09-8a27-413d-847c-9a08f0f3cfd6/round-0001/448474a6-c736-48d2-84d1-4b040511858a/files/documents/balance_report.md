## 4. 三种关卡和学习量的资源预算

为避免把 P18 不存在的掉落表当真实数据，设置**一次性首通试验值**：普通 3 训练代币+每角色 4 XP，精英 6+9，BOSS 12+18；同事件只发一次由 P17/P21 将来实施。数值是 P05 候选、非 P18 已签配置。

| 模拟首通构成 | 训练代币 | 每角色累计 XP | 可以购买的等级上升次数* | 剩余代币* |
|---|---:|---:|---:|---:|
| 1 普通 | 3 | 4 | 0 | 3 |
| 3 普通 + 1 精英 | 15 | 21 | 3 | 3 |
| 3 普通 + 1 精英 + 1 BOSS | 27 | 39 | 5 | 3 |
| 6 普通 + 2 精英 + 1 BOSS | 42 | 60 | 7 | 4 |
| 12 普通 + 4 精英 + 2 BOSS | 84 | 120 | 12 | 0 |

* 按 P04 fixture、三角色轮流优先升级、仅用关卡收益、无正式技能加伤、无重复首通；不是自动结算的真实玩家成长数据。完整预算见 `content/balance/stage_resource_budget.tsv`。

以同样假设的 3 普通 + 1 精英首通为对照，学习影子账本产生：

| 合成学习样本 | 有效不同事件 | 学习影子净代币 | 加关卡收入后代币 | 购买的等级升级次数 | 影响 |
|---|---:|---:|---:|---:|---|
| 零学习 ZERO | 0 | 0 | 15 | 3 | 零学习仍仅在“假想可打关卡”前提下有基础资源 |

## 5. 敏感性与决策建议

以“Lv1 平衡策略、125 HP 合成 BOSS、其他条件固定、同种子”为基准，单因素修改得到：

| 因子对照 | 结果 | 解释 |
|---|---|---|
| 基础 `damage_100` | WIN 20 回合，剩余 HP 81 | 当前测试基线 |
| 直接伤害乘 80%（取整） | LOSS 第 26 回合，BOSS 剩余 HP 2 | 很小的卡伤下降可能导致失败，敏感 |
| 直接伤害乘 120%（取整） | WIN 19 回合，剩余 HP 94 | 变化非线性，受牌序和取整影响 |
| 每回合能量 2 | LOSS 第 22 回合，BOSS 剩余 HP 9 | 低能量在此套牌可能不可行 |
| 每回合能量 4 | WIN 19 回合，剩余 HP 150 | 改动影响较大，必须与 P15 同步 |
| BOSS HP 100/125/150 | 16/20/23 回合胜利 | 时间成本随敌 HP 变化 |
| 护盾上限 20/40/80 | 此基线均 20 回合胜利 | 该对照没有触及 cap，**不能证明上限不重要**；另有 100 次堆盾极端反例 |
| 普通首通 2/3/4 代币 | 3普通+1精英预算 12/15/18 | 三种都足够 3 人 Lv2，但余量不同 |
| Again 等额1 vs 错误加倍2 | 20 次分别得 20 vs 40 | 错误政策制造失败作答的增益诱因 |

单回合费用压力反例：给定 3 能量，100 次消耗 1 的假想请求仅前 3 次可被数学门禁接受，97 次拒绝；**未运行 P14 的并发幂等**。跨回合堆盾反例：100 张各提供 4 的盾牌、累计支付 100 能量，40 盾帽生效总盾 40，不设实质上限生效 400；**不等于真实九张牌组可以单回合打 100 张牌**。

## 6. 可复算方式与真实验证层级

在解压包根目录（Python 3.10+ 标准库）运行：

```bash
python analysis/simulations/fixed_seed_simulation.py --seed 20261028 --verify
python -m unittest discover -s analysis/simulations -p "test_*.py" -v
```

重新输出（会覆盖**解压包自身**的 CSV，不写实际仓库）：

```bash
python analysis/simulations/fixed_seed_simulation.py --seed 20261028
```

模拟器先核对六个只读源文件 SHA-256，核对源版本卡牌/角色记录与参数表；任何源哈希变化将停止，不做隐式迁移。固定种子决定本地 xorshift32 牌序；CSV 记录 `model_version`、源 P02/P03/P04 SHA、参数 SHA 和 `seed`。`--verify` 不写文件，逐字节比较内置计算结果与交付 CSV。失败即退出非零，不准标 PASS。

**当前作者自测**：33 个 unittest 通过；44 条确定性结果落盘、复算字节一致。具体原始 stdout/stderr、exit code、Python 指纹保存在 `evidence/validation.log`。这是 P05 作者本地实现通过，不能替代 P32 独立测试或 P35 审查。

| 验收类别 | 结论 |
|---|---|
| 外层转交素材和内层 ZIP 文件完整性 | PASS：原字节与归档 CRC/manifest 校验 |
| 作者本地代码/数值/反例单测 | PASS：实际执行 |
| 作者离线固定种子复算 | PASS：实际执行 |
| 设计评审签署 | NOT_RUN |
| P13/P22/P08/P06/P18 跨岗契约 | BLOCKED |
| P14 真实游戏单元/契约/状态机 | NOT_RUN |
| 本地真正游戏/Anki 运行与双端 E2E | NOT_RUN |
| P32 独立测试和 P35 独立验收 | NOT_RUN |

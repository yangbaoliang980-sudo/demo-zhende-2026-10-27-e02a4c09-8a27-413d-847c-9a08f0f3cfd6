# P11｜学习事件账本状态机与实现说明

任务：`P11-S05-LEDGER-001`。交付：`P11-STUDY-LEDGER/0.1.0-isolated`。需求：REQ-011、REQ-012、REQ-025、REQ-026、REQ-029、REQ-030、REQ-039。接口关联：IC-16、IC-17、IC-18；向 P21 提交的存储请求同时关联 IC-19。

**本包有可执行的 P11 业务源码、持久化接口、作者测试及真实执行日志；正式 S05 接入仍为 BLOCKED。** `tests/support/` 中的钱包与 SQLite 存储均为明确版本的测试模拟器，不能作为 P17、P21 的正式交付。真实 Anki 样本为 0，实际游戏授奖为 0。正式路径未映射，所有改动限定在本独立包内。

## 1. 经核验的输入与实现边界

两份上传 ZIP 及递归内层 ZIP 已逐字节读取；16 个不同 ZIP、739 个文件成员通过 CRC；330 条 relay 清单记录和 P08/P09/P10 内部 202 条清单记录通过大小及 SHA-256 核验。三个上游完整包与 `demo-zhende…@d141284bc31ce08e4723259a0fbfdcdddc3780e5` 的 Git blob 对应；V6 正文与 `juesedemo…@8c370d731c323f86ff19642f4cc73f818498f641` 对应。来源清单和原字节快照见 `source_input_receipt.json`、`sources/`、`evidence/intake/`。

P08 的政策是 `P08-REWARD-POLICY/0.1.0-proposal`，四键金额、回收/补偿选择及批准记录为空；P09 正式激活映射为空；P10 的 `QUARANTINED.json` 明确身份、Undo、世代未验证。核验范围内没有 P13 实际路径映射、P12 正式协议、P17 WalletDelta、P21 物理事务实现或目标机证据。没有复用未经检查的历史模块，也没有把上游检查器当账本实现。

本轮因此实现引擎无关的 Python 业务模块。Python 是独立验证宿主，不是替 P13 决定游戏引擎。生产接口、鉴权、事件来源证明、日界与预算算法均待各 owner 接入；当前 DTO 是本地提案，不能宣称与 P10 原始事件格式兼容。

## 2. 四类身份必须分开

| 对象 | 本实现的身份 | 约束 |
|---|---|---|
| 原始收件 | 合法本地 DTO 规范序列化 SHA-256；非法输入用原字节 SHA-256 | 原始首份字节及哈希保留；只代表接收对象 |
| 来源操作 | 来源命名空间＋集合谱系＋固定权益归属＋经证明的 event_id | P10/P12 负责证明，不按 card_id、评分或时间生成 |
| 学习修正族 | 同一作用域＋经证明的 family_id | 原完成、Undo、恢复共用一个族 |
| 权益与交易 | 每族一个 entitlement key；每个来源操作一个 reward key | 政策、分类、日期、投递次数、游戏存档槽均不能制造新身份 |

`collection_epoch` 进入事实指纹并参与能力检查；它不会成为绕过旧权益的重新发奖开关。相同操作身份但 epoch 或其他事实载荷改变，形成冲突案件。不同操作身份但已存在同族、epoch 不同，也先隔离。跨 epoch 证明是旧事件时，仅允许有范围约束的 `LINK_DUPLICATE` 查询关联；不生成新 WalletDelta。真正需要迁移到新世代继续写入的合同尚未取得，仍须 P10/P12/P21 的新版本证据。

`beneficiary_id` 必须由可信接入层固定绑定权益归属，不能由 UI 自选；换游戏存档仍使用同一权益作用域。若上游不能证明这个绑定，`EvidencePort` 必须拒绝自动授奖。来源证明哈希是引用，不是数字签名；字符串或布尔值本身不构成授权。

规范序列化为 UTF-8、对象键排序、紧凑分隔、拒绝重复 JSON 键及非有限数。原字段不被语言模型猜测；格式变化不改变已经规范化的相同操作身份。

## 3. 唯一业务状态

StudyLedger 只使用以下五种业务状态。`ACK_RECEIVED` 是技术回执，`CONSISTENT_SNAPSHOT` 是只读对账报告结论，二者均不是新增账本状态。

| 状态 | 业务含义 | 可以改变钱包吗 |
|---|---|---|
| APPLIED | 有效事实对应的目标权益已经在同一原子提交中处理，存在提交凭证 | 仅使用经验证的 P17 候选 |
| REVERTED | 已证明撤销；无待回收/补偿差额，或从未授奖而只保存撤销墓碑 | 无原权益时绝不凭空扣款 |
| QUARANTINED | 身份、政策、映射、世代或冲突证据不足，需复核 | 否 |
| PENDING_RECONCILIATION | 刚持久收件、因果前序缺失、事务未确认、来源归属/已消费差额未决 | 未确认不宣称到账；已批准未消费回收可以与未决差额共同记录 |
| REJECTED | 确定非法输入或有绑定证据的拒绝决定 | 不以拒绝删除既有已授权益 |

入站记录与修正族投影分开保存。操作记录及审计保留历史结果；查询已关联的原完成时返回该族当前状态。因此原完成已被 Undo 后再投递，返回当前 REVERTED 或待对账状态，不重新授奖，也不把历史 APPLIED 显示成仍有有效权益。

## 4. 转移与优先级

| 当前条件 | 处理 | 后续状态 |
|---|---|---|
| 首次有效格式收件 | P21 持久收件，尚不计算权益 | PENDING_RECONCILIATION |
| 非法格式、未知 Schema、未知评分编码 | 保留原字节及原因，拒绝猜字段 | REJECTED |
| 身份/Undo/epoch 未证明 | 保存案件，默认门禁关闭 | QUARANTINED |
| 同身份同指纹重投 | 返回已有原子凭证及族当前状态 | 不新建权益 |
| 同身份不同指纹 | 单独隔离冲突输入，保留双方哈希 | QUARANTINED；原权益不受此冲突自动影响 |
| Undo 在原完成前到达 | 仅接受可信 rev=1/明确目标的控制事实，保存墓碑 | REVERTED；迟到原完成仍无奖励 |
| 因果前序尚未到达 | 持久等待；新前序凭证可支持复核 | PENDING_RECONCILIATION |
| 已发、全部未消费、回收获批 | P17 候选＋P21 同事务记录反向量 | REVERTED |
| 已消费或消费来源不可证明 | 记录权益暴露与来源；不扣其他来源 | PENDING_RECONCILIATION |
| 已证明恢复原事实 | 使用原政策/映射/原日快照，仅请求剩余差额 | APPLIED，或仍待对账 |
| 政策补齐、进程重启、再次点击 | 普通重投不自动改变隔离案件 | 保留原状态 |
| 新的、绑定输入和案件版本的复核证据 | 重判原身份，或证明重复后关联原结果 | 相应五态之一 |

控制事件必须包含经上游证明的因果链。`revision` 不是 P11 自造的时间序号；`predecessor_event_id` 必须指向当前链头。未知目标、跳号、陈旧或相互矛盾的控制请求不会扣钱。合法 Undo 接收不依赖“当前新授奖政策是否停用”；它使用已有授权快照。

## 5. 持久化和 ACK 边界

`ledger_runtime/service.py` 不导入 SQLite，不打开游戏存档，不读 Anki 数据库。它只调用 `ledger_runtime/ports.py` 的提案接口。

1. `receive()` 通过 P21 接口持久保存原始输入、指纹、收件状态和审计，成功最多返回 ACK_RECEIVED。
2. `process()` 在 P21 提供的可串行化快照内检查来源、去重、因果链和已批准政策。
3. P11 构造稳定的 RewardIntent，调用 P17 的纯计算接口；P11 不选择四键奖额，也不自行做消费归属计算。
4. 校验 WalletDelta 的操作/族/政策/钱包版本绑定、来源量、整数及守恒条件。钱包适配器取得深复制的输入，不能通过修改嵌套字典改写已固定政策。
5. P21 在同一物理事务中提交账本、来源权益、钱包、案件状态、审计及提交凭证。任何一步失败必须全部回滚。
6. P11 通过权威 `lookup()` 核验提交凭证后才返回相应 ACK 候选。正式发往 Anki 的序列化与含义由 P12 接收 RFC 后确定。

`execute_once(tx_id, request_sha256, decide)` 的回调方案是待 P21/P13 审核的进程内接口提案。回调不得做网络 I/O、外部写入或不可回滚副作用；P17 compute 必须纯计算。若真实 P21 采用候选＋CAS，则应由 owner 冻结等价原子语义、提交未知态和重试身份，再做契约适配，不能直接把 Python 回调当 IPC 协议。

收件事务与处理事务分开，处理事务 ID 从持久收件身份确定。处理提交成功但回复丢失时，重复请求查询同一提交；查不清则不出 ACK_APPLIED，不用新的交易身份绕开未知结果。多个并发消费者必须由 P21 唯一键及可串行化隔离兜底，不能依赖进程内缓存。

测试凭证的 `origin=P21_SIMULATOR`，所有回放记录均声明 `ISOLATED_SIMULATION`。包中出现的 ACK 字符串是候选语义的测试结果，没有发送给真实 Anki。生产 ACK 必须来自真正 P21 的受信适配器；校验 JSON 字符串并不能替代鉴权。

## 6. 撤销、已消费权益与恢复

P11 记录 P17 返回的逐资源审计量，复核上游 P08 的等式：

```text
A + S = G - R
G - R + M = T + U + K
全部为非负整数；U 与 M 不同时为正。
```

G 为累计记入，R 为累计回收，S 为可归属的已消费量，A 为该来源未消费量；T 为当前有效目标，U 为未决超额权益，K 为经批准重分类为补偿的量，M 为未满足差额。不同资源分别核算，不相加抵平。

**U 是审计差额，不是负余额、债务或未来自动扣款指令。** 来源归属不明时，不能用钱包总额冒充该事件剩余量。原来源可证明且政策允许时，最多回收 A；关卡或其他学习事件的余额不参与这次撤销。

本包复用了 P08-MATH-A01 至 A08 的合成量 Q=10：发10→花7→Undo回收3并记录U=7→恢复只补3，得到 G=13/R=3/S=7/A=3/T=10/U=0。再次 Undo 只再回收3。正式四键金额仍是 null。

尚无获批的 K 重分类、未来抵扣、跨币转换、角色降级或道具回收方案；本版没有实现这些资产操作。测试钱包遇到需这类方案的历史返回 HOLD，P11 保存 PENDING_RECONCILIATION。业务选择须 P08/P01 获批后以新接口版本实现，不能用“解决案件”按钮篡改余额。

## 7. 持久隔离与恢复入口

`pending_cases()` 从持久 `case_index` 提供待核验/待对账案件。每案保存输入哈希、首份原始输入、状态原因、版本、冲突关联、历史变迁及 P21 提交引用。时间流逝和重启都不是释放凭据；本版不自动清理原始审计或防重墓碑。

`resolve(inbox_id, evidence_ref, action)` 的允许动作只有：

- REPROCESS：在新增证据绑定原输入、当前案件版本和动作后，重新经过同一业务检查；不是直接设置 APPLIED。
- LINK_DUPLICATE：由可信证据证明与已有输入同一事实，只关联已有结果；强制同来源、谱系和权益归属。
- REJECT：有绑定证据的拒绝；不得拒绝已发生经济操作的原案件或有已授权益的族。

拒绝原完成后，普通 Undo/恢复不会重开它；需要针对被拒案件的新证据。所有复核记录追加审计，不改写原始证据。已结算的重复操作只查原结果；补偿政策变化并不借复核生成第二份全额奖励。

## 8. 旧备份对账与不能消除的缺口

`reconcile(checkpoint)` 只读比较独立 P21 检查点的实例、水位、账本哈希、钱包哈希、操作凭证及审计链。发现差异或缺检查点时输出 PENDING_RECONCILIATION，钱包修改次数为0。P11 不执行物理恢复，也不因为哈希相等自行解除 P21 的恢复栅栏。

模拟器会在观察到旧备份恢复时关闭写入并返回无 ACK 的背压；发送方必须保留未确认输入。模拟 P21 使用独立保留的权威副本恢复，旧分支另外归档，然后相同事件重放仍只保有原权益。这个测试证明的是在明确恢复栅栏及权威副本条件下的行为。

**如果账本、防重记录、提交凭证和检查点都被一起恢复到同一个旧版本，而外部没有可证明的水位，本地程序无法仅凭这些旧字节证明历史上是否已经发奖。** 本版不声称解决这种不可观测的整机回滚。真实 P21 必须提供不随该备份一起回退的权威证据或明确人工对账流程；否则自动授奖保持 BLOCKED。P10 尚未捕获入 outbox 的源事件同样不能由 P11凭空补采。

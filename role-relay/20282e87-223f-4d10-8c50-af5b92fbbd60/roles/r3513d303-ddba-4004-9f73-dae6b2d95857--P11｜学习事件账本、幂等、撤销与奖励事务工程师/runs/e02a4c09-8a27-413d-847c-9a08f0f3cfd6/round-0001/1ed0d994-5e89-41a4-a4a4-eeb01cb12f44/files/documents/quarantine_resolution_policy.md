# P08｜隔离、复核与释放权限规则

任务：`P08-S04-S05-POLICY-001`；版本：`P08-REWARD-POLICY/0.1.0-proposal`。  
隔离业务与实现 owner：P11。本文只定义政策候选与权限边界。

## 1. 隔离含义

### P08-Q01｜CONFIRMED：隔离不等于已发奖或作弊处罚

V6指定 P11 使用 APPLIED / REVERTED / QUARANTINED / PENDING_RECONCILIATION / REJECTED 业务状态。P08不新增可部署的账本枚举。本文的 `HOLD_*` 只是说明原因，需由P11/P12映射到正式状态/协议。

无法证明事件身份或Undo能力时，不授权发奖。P21持久保存隔离材料后，P12才可以按其合同发送 ACK_QUARANTINED；其含义是“已保管、未授奖、可查和可复核”，不能清除唯一审计轨迹，也不能让用户以为已经获得资源。

## 2. 隔离原因与解除材料

### P08-Q02｜PROPOSAL：按受影响事实设置最小范围

| 原因 | 最小范围 | 必要解除材料 | 证据责任方 |
|---|---|---|---|
| 身份/Undo不可证明 | 受影响来源、世代、目标版的新自动授奖 | 目标版本探针、脱敏样例、关联证明与限制报告 | P10/P12/P34 |
| 同身份不同载荷 | 冲突输入与关联案件 | 双方原始指纹和权威因果证明 | P10/P12 |
| 未知旧备份/迁移谱系 | 受影响来源历史与待授权益 | 集合世代与游戏事务水位的对账证据 | P10/P11/P21 |
| 缺PolicyRecord/适用版本 | 依赖该决策的待授权益 | P01转交的用户批准及哈希，明确生效界限 | P01 |
| 缺分类合同 | 依赖缺失映射的事件 | 固定版本pos_mapping_rules及UNKNOWN回退 | P09/P22 |
| 已有合法映射返回UNKNOWN | 不是独立作弊隔离原因 | 走批准的通用资源分支 | P09/P08 |
| 时间/日界证据不足 | 日相关兑现，不否定学习事实 | 事件发生依据、时区/边界版本及迁移规则 | P10/P34/P08 |
| 原事务结果未知 | 同修正族和关联差额 | 原P21权威提交/未提交结果 | P21 |
| 已消费或归属不明 | 对应事件/消费关系与补偿差额 | P17来源分摊、P01用户处置记录 | P17/P01 |
| 超已批准额度 | 本日对应资源的待兑现部分 | 批准的延期/封顶处置、原日预算账据 | P05/P08/P01 |

不因一个受疑事件自动冻结全钱包、关卡进度或其他可信来源。对原已授事件收到冲突载荷时，先隔离冲突项；未经核实不能直接使原权益失效。撤销后的负向变化和任何可用资产冻结均需已批准政策。

## 3. 权限与职责

### P08-Q03｜PROPOSAL：操作能力必须分开

| 动作 | 有权准备/执行的owner | 仍需什么证据 | 禁止越权 |
|---|---|---|---|
| 记录、查询隔离案件 | P11；UI由其公开接口读取 | 认证来源与P21持久回执 | UI直接改账本/余额 |
| 证明原事件/Undo/redo事实 | P10，经P12契约接收 | 目标版原始脱敏样例、哈希 | 用本规则文档证明Hook可用 |
| 纠正词类/提供UNKNOWN结果 | P09 | 授权字段、映射版本、纠错证据 | 借改标签重发整笔权益 |
| 解释已批准政策的适用性 | P08 | 具体PolicyRecord及事件事实 | 以“解释”增奖、减奖、创设债务 |
| 决定金额/豁免/抵扣/冻结 | 用户，经P01收集与归档 | 明确选项、影响范围、原文/哈希/版本 | P08/P11/P17自代用户批准 |
| 发起权益差额事务 | P11→P17→P21 | 证据充分、政策适用、原事务核实 | P08写钱包或P11直接落物理存档 |
| 独立自动化/人工复核 | P32 / P33 | 固定实现与运行记录 | 作者自测冒充独测 |
| SPEC/UNIT/CONTRACT/RUNTIME/E2E门禁 | P35 | 对应级别独立证据 | 一个静态PASS替代所有门禁 |

这些是业务权限要求，不是已部署账号角色。账号认证、操作审计和接口强制由P12/P13/P11相关owner设计并受独立验证。任何“管理员放行”按钮也不得绕过身份、来源和获批政策。

## 4. 从隔离到处理

### P08-Q04｜PROPOSAL：释放只允许基于新增证据

1. 固定原输入及哈希；同一案件新增证据追加版本，不改写原记录。保留来源作用域、事件/目标关系、收件版本、原政策及原奖励日、隔离原因、事务状态。
2. 收集责任方证据，区分“缺数据已补齐”“事实被证明不合格”“业务选择待用户”三类。超时、重复点击、系统重启都不是释放依据。
3. 证据证明是既有有效事件重放时，仅返回原回执。证明已Undo则进入原族撤销流程；不能为解除隔离新建另一学习事件。
4. 若可授或需调整，P11按既存唯一身份重新判定，P17核算差额，P21同一事务提交。恢复/重投不能重复享受原权益。
5. 结果未知时维持待对账并查询原事务；确认未提交才允许用同一请求身份重试。不能创建新事务业务身份绕过未知结果。
6. 释放后保留原隔离原因、补充证据、审核者、授权、事务结果和关联记录。被拒绝亦保留最小必要审计，允许凭新证据提出版本化复核，不能靠删除原记录重领。

如事实无法证明而用户决定善意补偿，可使用**独立获批补偿来源**，标明非学习奖励；不得伪造真实复习、改成可信事件或替用户选择Anki按钮。补偿仍要有范围、唯一键、预算与P21回执。

## 5. 人工门槛、保存与体验

### P08-Q05｜PROPOSAL：必须人工处理的情况

任何正的已消费差额、混合来源分摊不明、跨币变更、已豁免/抵扣后再恢复、无用户批准的追溯、来源世代歧义、无运行回执而宣称已发奖，均进入人工裁决。没有“小额自动放行”阈值。频率异常可提示复核，不能自动永久拒绝或扩大资产冻结。

建议用户可见说明分别表达“事件待核验”“政策待确认”“事务结果核对中”“已到账”“已撤销/权益待处理”；不把未发奖写成零收益学习失败。候选文案是本政策的含义说明，正式UI由其owner实现。

### P08-D05｜PENDING：保留期和升级规则

字段、保存期限、脱敏与清理规则需P38接收；当前不读取真实牌组内容，也不生成真实个人学习日志。不能因清理隔离记录同时删除尚需防重的身份墓碑。容量不足时应明确背压/停接收，而非静默丢弃或先确认后丢失；具体协议归P12。

同一问题连续两轮返工无新证据，应由P01组织裁决，保留原记录、双方base SHA与ChangeRequest。等待新材料不能冒充复测。涉及规则变更的复核需要新版本和影响清单，不能在本包的源快照中修补上游文件。

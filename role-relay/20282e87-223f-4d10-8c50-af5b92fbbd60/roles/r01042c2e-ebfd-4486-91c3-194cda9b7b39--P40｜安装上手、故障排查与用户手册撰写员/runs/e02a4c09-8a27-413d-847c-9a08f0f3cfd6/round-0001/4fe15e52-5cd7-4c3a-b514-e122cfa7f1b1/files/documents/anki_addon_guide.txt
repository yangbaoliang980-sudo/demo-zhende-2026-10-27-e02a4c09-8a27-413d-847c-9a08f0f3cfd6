3. 真实 Anki 评分的预期含义（需求而非已实现功能）
  Again / Hard / Good / Easy 属于 Anki 的评分选择；P08 候选规则要求合格事件基础奖励且 Again 重复不得无限叠加，Undo 需要撤回。实际资格、事件身份、连续复习及 Undo 链仍待获批/真机验证。
  P10 源码静态观察到 reviewer_did_answer_card(reviewer, card, ease) 与 state_did_undo(changes)，但前者没有显式持久事件 ID；单靠 card_id+评分+时间不能可靠判重。
  同卡再次出现，可能是合法重复复习，也可能是 Undo 后重答；未证实稳定身份/因果关联时必须 QUARANTINED，不得自称成功授奖。
  插件崩溃发生在复习提交之后、outbox 写盘之前时，队列重试不能自动恢复“未入队”事实；真实目标版仍需能力探针。

4. P12 隔离协议状态释义（不是当前游戏 UI 的真实文字）
  HELLO：协商严格协议版本和来源配对身份；无可接受交集不可连接。
  ACK_APPLIED：已查询到经验证的账本应用结果；当前只能证明隔离事务范围，不能代表正式游戏金币到账。
  ACK_QUARANTINED：事件已隔离持久化，不表示已授奖；继续查询/核对。
  RETRY_LATER：提交结果、因果关系或查询尚未明确；保留原 message_id/事件事实，不得改 ID 试图重新计奖。
  REJECTED：请求拒绝。传输前置拒绝可能没有持久收件凭证；必须保留输入并联系 owner，不盲目重发新 ID。
  STATUS/REVERTED：旧权益撤销，不作为新增到账确认。
  STATUS/NOT_FOUND：仅在可信完整性与连续性可确认时可用原始请求重投；绝不能从服务不可用推断 NOT_FOUND。
  PENDING_RECONCILIATION：可能存在已消费权益无法完整撤销；不得向玩家显示“确认没变化”。

5. 本地通信与断线补发
  隔离版 P12 采用 127.0.0.1 环回候选，临时端口和挑战/配对 HMAC；不是生产端口承诺，也不保证加密。真实部署要通过 Windows 端点权限/DACL、消息版本、停启和安全审核。
  出现断线/重启/响应超时：不要反复点击补领或删除 outbox；保持原始身份和请求摘要，只读查询状态、记录日志；未建立生产协议时不尝试用户级补发命令（NOT_AVAILABLE）。
  本轮没有经核实的正式 UI“同步成功/奖励已到账”的显示控件，不能让用户据此推断实际钱包数值。

6. 停用/卸载的边界
  插件开关位置、正式 addon ID、outbox 文件位置、重装是否清理缓存：NOT_AVAILABLE。
  Anki 原有复习计划不能因游戏失效而被改动；撤销应通过 Anki 正式操作进行，不能手工编辑数据库。出现问题优先保持原学习数据完整并停止游戏奖励链操作。
  任何重装/删除必须先使用正式版列明的备份/保全流程，不能删除未确认投递记录。

# P23 信息架构与既有页面边界

版本：P23-IA/0.1.0-proposal。任务：P23-S03-S06-UX-001。S03 为本轮优先；S05–S07 只对齐已收到的 P20 界面，不宣布后续功能启动或完成。正式路径仍 BLOCKED。

## 入口与主路径

学习状态 → 旅团营地 → 角色档案 / 三人编队 / 角色养成 → 章节远征 → 已有出战交接态 → 卡牌战斗 → 战后结算 → 章节或养成。

学习页不是每次战斗前的强制关卡。Anki 未连接不等于钱包无效，也不自动使已获准的单机操作失效。章节能否出战由既有 P18/P20 资格决定；本设计不补零学习日资源规则。

| 既有页面 | 用户首先需要知道什么 | 主要操作与真实领域边界 | 本轮对应线框 |
| --- | --- | --- | --- |
| 营地 home | 已保存编队、当前资源、学习连接是否可用 | 导航只读；同步只读 | W07 |
| 角色档案 characters | 角色身份、定位、当前等级 | 进入同一角色的养成；不创造新角色 | W14 |
| 三人编队 party | 当前草稿与已保存顺序是否不同 | 选择只改本地草稿；明确保存才 SET_PARTY | W08 |

## 战斗画布的阅读顺序

1. 页首：回合、可用费用、动态效果选择。
2. 持续状态条：操作条件、等待/未知/断连的原因及下一步；不只用消失式 toast。
3. 战场：我方三席与敌方卡面。敌名、生命当前/最大、护盾、行动类型、目标、基础量与次数保持同时可读。
4. 最近结算：实际生命减少与护盾吸收分列；取已提交事件，不能拿卡面基础值冒充结算值。
5. 手牌：名称、费用、类别、效果、归属、选中/不可用说明。五张示例不构成手牌上限。
6. 操作行：完整记录、详情、取消、确认出牌、结束回合。目标选择不会自动出牌。

敌人头像区域只是尺寸标记，不是正式怪物资源。图片缺失时名称、数值、意图仍存在。动态效果关闭时该阅读顺序不变。

## 元界面的全局信息

左侧沿用 P20 的七项导航。营地正文的快捷按钮与侧栏是不同控件，拥有不同固定锚点。连接提示在侧栏和学习正文引用同一连接事实；两处不能分别缓存而产生相反文案。

钱包必须标注“当前可核验”或“最近确认”；未读到值显示“— / 尚未取得”，不写 0。测试模式和正式接入状态在外层提示，但不让内部 request_id、SQL、hash、代码枚举占据玩家的首要信息层。

存档只读、迁移、恢复待核对、不可用，均在正文前保留提示。用户仍可浏览。具体暂停范围沿用 P20/P21 的已接受保护条件；单条隔离学习记录不会自行触发整个钱包冻结。

## 跨页面状态保留

- 草稿：选择不等于保存，已保存顺序独立展示。恢复已保存编队只清除草稿。
- 未知操作：不能用新身份代替原意图。P20 已有本地待确认恢复设计，正式查证 gateway 仍受阻；P19 当前只在内存保留原命令，通过同 ID 重发查证，完整页面重载不具备持久恢复能力。正式恢复须 P13/P14/P21 受理，不能套用 W11 的元系统恢复语义。
- 活动战斗：返回章节不会自动关闭或重新创建。正式 P20 → P19 路由受理缺失时只显示现有交接状态。
- 战斗终局：只读 P14 outcome。WIN / LOSS / DRAW / ABORTED / FAULTED 文案不同；前四者也不推导奖励到账，FAULTED 显示核对与恢复入口条件。
- 奖励：挑战进度、首通资格是否已消耗、领取请求状态、可用余额分别显示。查证或隔离不让已消耗资格重新变成可领。

## 冻结与验收边界

`information_architecture.json` 是机器可读映射；`ui_state_map.json` 列出 screen_id / widget_id / states / focus_scope / anchor_id；`interaction_state_matrix.tsv` 是逐态行为。三者必须同版本接收。

未新增设置、装备、商店、PvP 或探索页面。装备内容保持上游“功能未开放”的范围，未画正式装备交互。结束回合前的行内确认属于本岗交互提案，须 P01/P19 受理；未在游戏中实现。

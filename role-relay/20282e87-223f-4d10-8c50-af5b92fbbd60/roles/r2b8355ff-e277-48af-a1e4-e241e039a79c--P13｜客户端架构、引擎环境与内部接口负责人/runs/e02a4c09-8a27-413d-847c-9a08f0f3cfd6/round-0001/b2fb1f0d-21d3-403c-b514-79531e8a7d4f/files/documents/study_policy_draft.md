## 1. 使用边界与来源

本文件是 S04 能力观测所需的语义输入及 S05 候选政策，不是 Hook、账本、钱包或存档实现。所有正文规则按标题或表格行标为 `CONFIRMED`、`PROPOSAL` 或 `PENDING`。`CONFIRMED` 只确认相应的既有约束，不表示奖励数值、运行合同或独立门禁已批准。

来源为实际解包核验的 P01 `P01-S00-V0.1`、P05 `P05-BALANCE-0.1.0-provisional`、P07 `P07-STAGES-0.1.0-proposal`，以及 GitHub 固定提交 `8c370d731c323f86ff19642f4cc73f818498f641` 的 V6 冻结原文。源文件、具体 ZIP 内路径及 SHA-256 见 `design/anki_rewards/source_input_receipt.json`。P01 的历史激活表不代表本次激活状态；本次用户指令启动 P08 的独立政策交付。

`policy_registry.json` 是规则索引，`policy_record.proposal.json` 是未签署政策记录，均不是可部署授奖配置。本文引用的 `F`、`B`、`Q`、`reward_day` 等是语义符号，不是已冻结的 P12 Envelope 或 P13 DTO 字段。名称和字段须由相应 owner 接收 RFC。

### P08-C01｜CONFIRMED：既有硬约束

- 游戏收益来源必须是真实 Anki 桌面复习；不改变 Anki 调度，不写 Anki 数据库。不以按钮点击、展示答案、游戏 UI、自填时长或临时 Mock 代替完成事件。关联 `REQ-011`、`REQ-025`、`REQ-026`。
- Again 不能仅因“未记住”被判为无效；评分是学习反馈，不是可信身份或反作弊证明。奖励不能逼迫用户选择 Easy。
- 真实权益最多对应同一有效事件的一份有效授权；消息重发、换协议版本、换政策版本、换分类、换游戏存档均不天然产生第二份权益。
- P10 未能证明目标版的事件身份或 Undo 关联能力时，停止该来源范围的自动授奖方案，由 P11 隔离。等待几秒或几天不能替代 Undo 能力证明。
- 未取得 P01 转交的用户书面政策批准，P11 不得据本草案真实发奖。默认不制造负余额，不不可逆删除道具，不自动回退角色等级。
- P11 拥有学习账本业务，P17 拥有钱包业务，P21 拥有物理事务，P12 拥有跨进程协议，P13 拥有内部 DTO，P22 拥有正式内容 ID。P08 不代行这些实现。

### P08-C02｜CONFIRMED：批准、来源可信、到账是三个条件

“可信复习”回答发生了什么；“符合奖励政策”回答是否取得何种权益；“已到账”必须有 P21 的持久提交凭证。三者不能互相替代。`ACK_QUARANTINED` 仅表示已持久保存待查材料，不能显示为奖励已到账。四键按钮在目标版的数值编码没有输入证据，本版只使用语义名 Again / Hard / Good / Easy，不假设 1—4 对应关系。

## 2. 术语与证据要求

### P08-P01｜PROPOSAL：复习资格分层

| 层 | 判定要求 | 不满足时 |
|---|---|---|
| 来源层 | P10/P12 认可来源，版本与 P34 指纹一致，受限权限采集；非 UI 自报 | 隔离或按协议拒绝，不发奖 |
| 完成层 | 真实完成提交证据、四键语义可解释、未被更高可信撤销/修正否定 | 等待因果信息；仅预览不构成有效复习 |
| 身份层 | 可区分集合来源、世代、每次完成身份、撤销目标、合法重做；可应对恢复旧备份 | 不猜测，不用 card_id/毫秒时间代替 |
| 政策层 | 适用且已批准的 PolicyRecord、分类表、经济预算、权益归属与生效界限 | 保留待审事件，不使用最新政策倒推旧事件 |
| 交易层 | P11/P17 候选经 P21 同事务提交，并有唯一回执 | 未到账；结果未知先查回执 |

“真实合格”与“因已批准封顶暂不能兑现”应分开。合法但待分类、待对账、待容量的事件不得显示为“学习无效”。受疑事件也不能被直接宣称为作弊。

### P08-P02｜PROPOSAL：身份与修正族

1. 来源事件身份须由 P10/P12 证明。逻辑上需要来源命名空间、集合谱系/世代、原生复习身份等区分量；本文件不规定这些量在 Anki 中必然存在。
2. `F` 表示同一复习事实的修正族。原复习、对它的 Undo、恢复原事实、已证明替换原事实的重答，必须能关联到同一个族。技术消息 ID、事件修订号和业务权益身份应区分。
3. 没有撤销关联的、正常调度形成的同卡下一次真实完成是另一个事件，不能因 card_id 相同强行并入前一次。反之，改评分后重发同一身份不是新的合法完成。
4. 同一 `F` 的有效目标权益向量最多一份。分类或政策版本不进入可绕过唯一性的“新奖励键”；资源向量的多项组成也不是多次发奖。
5. 跨集合导入、克隆、旧备份、重装插件、切换或恢复游戏存档，必须先证明谱系与已消费历史。无法证明时隔离受影响范围，不能通过创建新世代或新存档规避历史。

## 3. 判断优先级

### P08-P03｜PROPOSAL：控制事件先于新增授奖

下表是语义偏序与冲突优先级，不是规定 P11 的实现状态机。认证、解析和持久接收仍由对应 owner 完成。

| 顺序 | 命中条件 | 候选处理 |
|---|---|---|
| 1 | 格式非法、来源不被授权、版本不兼容 | 按 P12 已批准错误语义拒绝/隔离；不得猜字段或发奖 |
| 2 | 同一身份且指纹完全相同 | 查询既存结果；无额外权益。查询不受“新政策尚未批准”阻挡 |
| 3 | 同一身份不同指纹、谱系碰撞、未知因果顺序 | 隔离冲突输入。保留原记录，不因新冲突自动追回原已发收益 |
| 4 | 已验证 Undo / 恢复 / 权威修正 | 先处理目标关联；比该目标的迟到原完成优先。新授奖暂停不能导致 Undo 丢失 |
| 5 | 原完成已被撤销、目标尚未到达、族内已有未决余额 | 保留撤销墓碑或待对账记录；迟到原完成不重开权益；不额外给重答发奖 |
| 6 | 新增完成但身份或 Undo 能力缺失 | 全部相关四键统一隔离；Again 与 Easy 均不得例外 |
| 7 | 未签政策、映射/经济版本/权益归属/生效范围缺失 | `HOLD_POLICY`，不是默认奖值 0，也不是无限额 |
| 8 | 复习未完成、事件类型不支持、未知评分语义 | 不授予；可复核异常与确定非复习事件分别保存原因 |
| 9 | 事件日期、分类与数量已可确定 | 固定事件适用的政策、分类、原奖励日和单位；检查已批准预算 |
| 10 | 确有新增或恢复的权益差额 | 交 P11/P17/P21 计算并提交；到账以权威提交回执为准 |

同时命中撤销和重复原完成时，以已有可信撤销结果回答重复请求。Undo 先到而原事件未到时，记录目标关系；没有原事件可供回收时不凭空扣款。控制事件本身同样要来源认证和去重，陌生撤销消息不能损害已授权益。

## 4. 四个评分键

### P08-P04｜PROPOSAL：推荐等额基础收益，实际数额待批

固定同一真实事件证据、同一类别、同一额度状态时，推荐 `Q(Again)=Q(Hard)=Q(Good)=Q(Easy)=B(category)`。`B` 是待 P05 核算、P01 取得用户批准的非负资源向量符号，**不是 1 代币，也不是已批准正数**。

| 评分 | 是否可能是真实合格复习 | 推荐候选 | 奖励附加条件 |
|---|---|---|---|
| Again | 是；不能因评分低而否定 | 与其他三键同一基础向量 B | 不加“记错奖励”，不扣收益 |
| Hard | 是 | B | 不因困难降档 |
| Good | 是 | B | 不给额外正确率奖金 |
| Easy | 是 | B | 不给额外币、稀有率、卡牌强度、体力或排名优势 |

`four_rating_policy_matrix.tsv` 展开同一组条件下的四键结果。其 `current_real_award_authorized=false` 对所有行成立；`formal_amount=UNSET` 表示未知，不是数值零。候选行为用于下游编写测试，不授权生产发奖。

### P08-D01｜PENDING：不等额方案必须重新提案

`DEC-001` 由 P01→用户决定。候选 A 为四键等额；候选 B 为同额基础加评分差额（差额未指定，需说明行为风险）；候选 C 为无物质差额、仅中性的学习反馈。P08 推荐 A，并允许 C 的非奖惩反馈；B 不作为本版可执行分支。P05 的 Again=2、其他=1 是反例，不能转为政策。Easy 高收益同样会诱导错误自评。

等额只能证明**固定单次机会**没有评分差额，不能证明长期无刷取诱因。故意 Again 若增加后续完成次数，按次计奖仍可能产生收益优势。P39/P05 需比较正常复习、反复 Again、Undo/重答、同卡正常重复等完整行为路径；不得用“等额”替代该评估。若需按学习 episode 限额，必须先由 P10 证明可识别，再由 P01取得用户批准，不能擅自把同卡每日一次设为事实。

### P08-C03｜CONFIRMED：UNKNOWN 与缺整个映射合同不同

V6 的 P09 要求未知字段稳定回退通用资源。**已有批准的映射版本返回 UNKNOWN**可走其通用分支；**整个映射配置/版本缺失**不能假装已有 UNKNOWN 规则并授奖。不得读取未经授权的整套牌组或联网猜词性。

### P08-P06｜PROPOSAL：向量、快照与事务时点

一个复习族产生一份带来源和版本的权益向量；同一事件的“基础量”和“类别量”若只是两种显示，不得重复加总。每一项绑定单位、数量、舍入、溢出与存储上限。不得将不同币种或角色 XP 直接相加。

首次合格判定固定政策版本与映射快照。后续标签纠错不产生第二笔全额奖励；需要替换类型时按已批准的差额/补偿流程，未消费且可追溯部分方可讨论转换，已消费部分进入人工裁决。政策升级也不能让旧事件按新版本重领。

发放顺序：真实完成证据 → P11 判定/去重 → P17 WalletDelta → P21 将学习状态、权益与审计一次性持久化 → P12 ACK。无提交凭证时 UI 显示待处理；确认丢失时查原事务，不能新建学习事件来补发。授权策略、原子合同与错误码均待正式接收。

## 6. 跨日、离线与封顶

### P08-P07｜PROPOSAL：奖励日不能由到达时间决定

奖励日策略需固定时区、边界和版本。尚无目标 Anki 证据，不假设午夜或任何默认换日时刻。完成瞬间及当时已批准的日界规则确定原 `reward_day`；服务收到消息的时间不能重置它。Undo 与恢复沿用原族的日期、政策和容量归属。

- 跨日首次收到的旧完成：归原日；若原日适用版本未知，隔离待复核，不按今天高奖值发放。
- 同一事件在新一天重发：返回原回执，不取得新日权益。
- 跨日新发生的不同合法完成：可有新事件资格，不因同卡而否定。
- 跨日 Undo / redo：对原族调整；不消耗第二个新日配额，也不能借换日洗掉未决差额。
- 时钟回拨、手工改时区、夏令时边界歧义、旧备份回退：保留事件与时间依据，不能静默重分桶。无法证明归属时暂停日相关兑现，学习事实保持可复核。
- 延迟或离线不是作弊证明；历史补发是否追溯、最长保留期、政策迁移均 `PENDING`，不编造截止天数，也不承诺无限期补奖。

### P08-D02｜PENDING：经济封顶及公平性

| 候选 | 规则 | 代价与门禁 |
|---|---|---|
| CAP-A | 经用户明确批准后不设每日经济上限 | P05 证明长期产出/用途，不能将 null 当无上限 |
| CAP-B | 每来源权益作用域、每奖励日、每资源单位的已批准预算 C | 对四键一致；正常大量学习不能被标为作弊 |
| CAP-C | 软封顶后暂存待兑现 | 需说明兑现期限、额度保留与上限；未批准不得许诺欠付 |

预算跨所有相关卡组/类别聚合，避免切标签或卡组重开额度。币种不同分别计量，跨币价值权重须 P05 批准。边界候选为“完整一个权益包入账，否则完整待容量复核”，避免自行舍入或静默删尾数；部分发放需另签版本。

若采用封顶，推荐配额预留绑定修正族与原日。Undo 不自动释放可反复利用的授奖机会，redo 复用原预留；释放只在证明无未决/保留权益并获批的规则内执行。该选择可能影响误操作后的可得收益，必须经 P01 用户批准。所有上限、权重、速率、保留期限为 `null/UNSET`；缺少明确选型时自动授奖保持 BLOCKED。

## 7. 撤销与重做

### P08-P08｜PROPOSAL：四类情况必须区分

| 情况 | 候选处理 |
|---|---|
| 授奖提交前已验证 Undo | 目标事实失效、待授权益取消；保留墓碑，不发也不扣 |
| 提交后 Undo，原来源未消费部分可证明 | 按获批原量回收候选；不回收无关关卡/其他事件余额 |
| 已消费、归属不清或并发结果未知 | 进入补偿/对账；不猜余额、不制造负数、不降级/删道具 |
| 已证明恢复原复习或替换重答 | 复用原修正族，根据当前保留/回收事实仅计算差额 |

原事件被撤销后出现同卡新回答，不足以证明是 redo；P10需区分“原事实恢复”“替换重答”“正常下一次复习”。未观测到关联不能简单将它当新奖。已消费后仍保留的权益在恢复时计入已给部分；不能“保留旧道具 + 再发完整新包”。若已执行未来抵扣/豁免或跨币转换，先走关联对账，不自动套用未消费恢复公式。

具体选项、算术和人工阈值见 `undo_compensation_options.md`、`quarantine_resolution_policy.md`。本版所有数值算例为独立数学夹具，真实已发金额为未知，实际发奖次数为 0。

## 8. 反刷边界与关卡分域

### P08-P09｜PROPOSAL：先解决重复，不凭表现处罚

确定防重对象是重复身份、伪造来源、冲突载荷、已撤销旧事实及旧备份重放。短作答时长、只按 Again、复习量大、同卡多次、离线批量上报只能形成观测信号，不能单独判作弊、永久失权或扣奖。阈值和人工审核队列容量都未批准。

能力不足只暂停受影响来源/世代/版本的新自动授奖，正常查询、合法撤销接收、证据保存与 Anki 自身学习继续。不能因一次输入冲突冻结无关已得钱包或关卡。

### P08-P10｜PROPOSAL：与 P07 的边界候选回执

学习、关卡首通、关卡重复、用户批准的补偿为不同业务来源，即使共用币种也保留不同来源和事务关联。Anki Undo 不撤销可信 BattleResult、不删除 stage 首通键、不自动回滚章节、角色等级或卡牌。关卡结果撤回仍由 P18 处理。首通、重试或关卡 XP 也不能伪装为学习完成或占用学习事件身份。

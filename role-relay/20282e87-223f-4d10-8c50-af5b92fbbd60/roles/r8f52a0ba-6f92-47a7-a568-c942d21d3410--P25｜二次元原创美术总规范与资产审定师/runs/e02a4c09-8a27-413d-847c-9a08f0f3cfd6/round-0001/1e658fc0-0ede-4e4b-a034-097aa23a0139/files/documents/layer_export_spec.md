# 分层、透明度与导出规范

版本：P25-LAYER-EXPORT/0.1.0；相关 IC-22 的 owner 为 P30。本文件是 P25 的制作/审查要求与导入建议，不是已受理的引擎导入配置。

## 1. 真正可编辑的源

接受 PSD、KRA、CLIP 或能保持实际绘制能力的其他原生源；记录应用和准确版本。OpenRaster 可作为开放互通副本，不能替代丢失蒙版、混合模式或矢量信息的原生工程。SVG 适合 P24 UI 与本规范的矢量指南，不自动满足角色绘画原稿要求。

| 建议层组 | 应保留的编辑能力 | 验收动作 |
| --- | --- | --- |
| `00_guides` | 画布、安全线、比例线；默认不导出 | 单独隐藏，成品不得留下红青线或文字 |
| `10_sketch` | 草稿/结构稿，可隐藏 | 不要求成品仍显示草稿 |
| `20_back_hair` | 后发与前发的遮挡关系 | 关闭前发后能理解头部层次 |
| `30_body_skin` | 肤色与衣服色块可分开调整 | 改肤色不连带把衣服染色 |
| `40_outfit` | 服装底色、主阴影、接触暗部 | 改服装主色，线稿和肤色不被破坏 |
| `50_face` | 眼、眉、嘴至少能独立调整 | 一个表情局部修改可重导出，脸型不漂移 |
| `60_front_hair` | 前发主要体块、阴影、高光 | 发色调整不破坏脸部 |
| `70_hands_props` | 手/道具前后遮挡可理解 | 修改握持接点，不重画整个身体 |
| `80_light_fx` | 反射光、魔法光可关闭 | 关闭后仍有完整人物与主色 |
| `90_background` | 审查底色独立且可隐藏 | 透明导出确实包含 alpha=0 的区域 |

层组名是语义建议，不强迫特定软件命名；送审 `layers.json` 需映射同等能力。不得复制一张合成图到多个组凑层数。无需把每根手指都拆成骨骼素材。

本包 `character_source_template.ora` 按 ORA 结构生成命名层组与空白绘画层，只有指南层含测量标记；容器与 PNG 结构可复验，绘图应用实际打开为 NOT_RUN。它的元数据明确 `TEMPLATE_NOT_ART`，禁止通过样本门禁。

## 2. 开源互通模板结构

ORA 内 `mimetype` 为首个不压缩成员，内容精确为 `image/openraster`；`stack.xml` 引用真实 layer PNG，包含 `mergedimage.png` 和不大于 256×256 的缩略图。这些仅证明容器结构；是否有真实可编辑绘画须在绘图软件实际打开、切层和重导出后检查。参考 OpenRaster File Layout Specification 与 Layer Stack Specification。

## 3. 导出约定

| 项目 | 本轮规格 |
| --- | --- |
| PNG | 无损，RGBA，每通道 8 bit；不把 JPEG 改扩展名 |
| 色彩 | 按 sRGB 制作；记录 `sRGB` chunk 或 ICC 是否存在及哈希；缺元数据要显式说明 |
| Alpha | PNG 保存未预乘/非关联 alpha；不把黑/白底合成后冒充透明 |
| 画布 | 立绘与差分保持同尺寸、原点、锚点；不自动 trim/rotate |
| 导出比例 | 按 `crop_profiles.json`；源尺寸可以更大，严禁非等比拉伸 |
| 背景 | 棋盘/浅底/深底仅用于证据图，正式透明图不含这些背景 |
| 命名候选 | `<asset_id>__<variant>__v001.png`；内容 ID 及注册规范由 P22 受理 |
| 图集 | P30 决定 padding、extrusion、压缩、mipmap、过滤；P25 不代签实际参数 |

文件名、metadata 声称 RGBA 不等于实际 RGBA；检查器需解码文件、检查模式与 alpha 分布。alpha=0 像素中保存的 RGB 值本身不能证明预乘或污染；边缘还要实际合成到浅/深底观察。2× 切图不是通过最近邻放大 1× 后自动合格。

## 4. 锚点与裁切

原点统一为图像左上。矩形顺序是 x/y/width/height，九宫格顺序为 left/top/right/bottom；P30 转换实际引擎顺序。归一化锚点的 x/y 范围为 0—1。必须注明锚点基于母版、透明导出还是裁切图，不混用。

源到裁切使用可复查的 crop rect 与等比 scale；若采用重新构图，另建 variant 并引用同一角色/敌人 ID。发饰或武器允许越界的区域单独登记，脸、视线、握持接点不得靠框边裁掉。P24 透明孔内的安全矩形是审查建议，需要真实人物/敌人后复核。

## 5. 导出检查步骤

1. 从固定源版本导出，记录源字节和 SHA-256；不得先改源后沿用旧哈希。
2. 实际解码所有图片；检查目标尺寸、alpha 通道、非全透明、格式和文件名唯一性。
3. 在白、墨紫与棋盘背景上看完整图和边缘；100% 看头颈肩、四肢、手与道具，200% 只作为问题定位。
4. 同时查看规定尺寸头像、小窗和横向裁切；保留文字/框/焦点/选中层后的证据。轮廓太小需专用裁切，不缩小 UI 字体补救。
5. 在原软件关闭背景与特效、修改一个局部并重新导出，证明真实可编辑。保留应用版本、操作记录和修改前后图；机器只检查文件结构，不能代替该步骤。
6. P25 给审美结论；P37/P30/P35 分别补独立回执。检查器返回“技术上可送审”不等于正式美术已通过。

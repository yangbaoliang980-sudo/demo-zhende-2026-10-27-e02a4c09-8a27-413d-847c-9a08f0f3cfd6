## 2. 可执行的整体审美

### 2.1 核心语言

人物采用清楚的二维动画线稿、柔和的脸部轮廓、主辅分明的发束、两段为主的赛璐璐阴影和少量柔光。画面首先让人读出脸、眼神、手势与一个主要识别物。背景保持低细节、低对比，以人物为中心；不依赖 3D 场景或骨骼动画才能成立。

UI 采用 P24 已有的墨紫底色、奶白正文、淡金选中、冰蓝焦点。角色与敌人的服装或饰品可以呼应墨紫、旧纸白与哑金，但不能把整张角色画成同色的 UI 面板。人物主色和情绪辨识仍由 P04 设定与 P26 构图完成。

“书页、书签、旅途携具、简洁的几何徽记”是可用的装饰语汇，不是已经批准的世界观事实。每名样本最多突出一个主题识别物和两处呼应，避免无功能的满身符文、金属边与粒子。具体名字、发色、瞳色、年龄设定、服装身份、武器与性格不得从 P20 文字占位自行推断。

### 2.2 层级与观察顺序

| 层级 | 需要先读出的内容 | 审查方式 |
| --- | --- | --- |
| 第一层 | 脸、视线、主体轮廓 | 缩小至目标卡面仍可区分头部朝向；不被头饰与特效夺走注意 |
| 第二层 | 手势、握持关系、服装的大色块 | 100% 检查手腕—袖口连续、手与道具接触；灰阶中仍有大面分离 |
| 第三层 | 扣件、纹样、材质差异 | 只在近看时丰富；不成为头像识别必须依赖的细节 |
| 交互层 | 当前/最大生命、费用、意图、操作条件 | 由 UI 真实文字承载；美术底图和特效不得覆盖 |

人物优先不意味着减少文字可读性。背景与人物高亮若冲突，应降低背景细节或更换裁切，不能用缩小关键字体补救。

## 3. 比例、脸型与五官

以下数值是本项目的绘制起点和一致性检查带，不是人体学事实，也不是自动判定“美观”的算法。正面中立姿势用于量尺；透视、俯仰、弯腿或发饰不直接套正面数值。偏离后提交说明与并排样本，由 P25 判断。

| 项目 | 本轮单人样本基准 | 观察与退回标准 |
| --- | --- | --- |
| 头身 | 6.0—6.5 个头高，样板以 6.25 为中心 | 头高从颅顶到下巴，不含发饰；脚底到颅顶测全高。不得一张 6 头身、另一张无说明变成 3 头身 |
| 肩宽 | 正面约 1.35—1.60 个头宽 | 肩线接颈根，左右锁骨有结构；不得用衣领掩盖错位颈根 |
| 脸型 | 软椭圆，颧侧收束，下颌两侧自然转折 | 不做针尖下巴；近侧与远侧脸颊遵从同一透视 |
| 正面眼线 | 颅顶至下巴的约 0.50—0.57 | 侧脸与仰俯角改用透视辅助线；不能强行保持水平双眼 |
| 双眼布局 | 每眼约头宽 0.21—0.25，间隔约 0.18—0.24 | 先确定头的朝向再放眼；两眼瞳孔朝向同一目标，非故意表情不得散焦 |
| 鼻口 | 鼻尖约头高 0.68—0.75，嘴线约 0.78—0.85 | 仅正面设计参考；口腔与嘴唇结构不重复、不漂浮 |
| 身体大关节 | 肩、肘、腕、髋、膝、踝有连续受力关系 | 肢体连接和握持错误为硬退回，不以“二次元风格”豁免 |

虹膜保留主色与一层较深上缘；每眼主要高光 1—2 组，遵从同一光源。睫毛主线明显，鼻与嘴线轻；不把皮肤轮廓、鼻梁、唇线都画成等粗黑线。耳位、下颌、颈根在同一个头部体积上解释得通。

先用正面或轻三分之二角度完成一个样本，验证关键部位；本轮不增加完整动作组、三视旋转动画或骨骼拆件要求。后续表情沿用同一头部底稿与眼线，不重新生成另一张不相似的脸。

## 4. 发型、服装与角色差异化

发型先拆为 3—5 个主要体块，再画次级发束。额发、侧发、后发有清楚遮挡次序。两侧用于识别的轮廓在对应裁切中保留；少量飞发可出安全线，但不得让被切掉的飞发承担唯一身份信息。头发高光沿发束曲面走向，避免每束都贴同样的白色圆条。

服装控制为一个主体剪影、一个功能层、一个主要饰物。接缝、腰带、扣件要能解释穿脱和受力；布料褶皱从肩、肘、腰、膝与扣点展开。胸口、袖口、腰间不能用无来源的阴影制造多余肢体或穿模。

材质建议为软布料、硬挺旧纸/皮革、少量哑金金属。使用配套的材质测试格：布料大面积哑光、纸张平整弱纹理、金属窄而有方向的高光。禁止全身同样油亮、皮肤塑料质感、纤维噪点压过脸部。

后续多角色并排时，优先通过发型轮廓、外套长度、道具轮廓、姿势和主色区域区分；不以大量新增服装配件拉高成本。本版色板的暖色/冷色仅是可选辅色，不能直接指派给“璃火/千澄/羽铃”等历史占位名字。

## 5. 线条、色彩、光影与材质

### 5.1 线条

以 2048×3072 母版为参考：外轮廓常用 6—10 px，内结构 3—5 px，脸部细线 2—3 px；压感收尾、遮挡处略重，受光处可轻。它们是可调笔刷区间，不是导入参数。重要的轮廓必须通过 50% 导出与实际小窗复核；线宽随图形下采样，不在头像上简单套全身笔刷。

优先采用带色深线 `art.line`，允许按肤色/发色略偏色。连接处闭合清楚，不出现重复手指线、短杖断裂、书脊悬空。PNG 抗锯齿保留透明过渡，不以模糊整个角色掩盖边缘。

### 5.2 色板

机器可读色值见 `palette.json`。UI 语义色继承 P24；本轮接受其用于 S03 占位设计。角色色板是样本方向，不是已登记的角色身份色。

| 用途 | 色值 | 使用边界 |
| --- | --- | --- |
| UI 底色 / 信息底板 | `#121520` / `#202535` | 真实文字后方保留实色底板 |
| 主文字 / 辅助文字 | `#F5F1E9` / `#C0C9DA` | 原因、费用、生命等不使用更浅透明度弱化 |
| 主操作 / 深色按钮字 | `#D8BCF4` / `#19192B` | 浅底用深字，不能照搬深底白字 |
| 选中 / 焦点 | `#E6BF7D` / `#97E2F6` | 选中有勾号/双框；焦点为独立外框，可同时出现 |
| 美术线色 / 浅布 / 墨紫 | `#3B334B` / `#F3EBE0` / `#71608E` | 与 UI 呼应，人物不被底板吞没 |
| 冷紫阴影 / 哑金 | `#A79AB9` / `#C6A56C` | 阴影需结合局部固有色，不能无差别覆盖所有材质 |

单人主体画面通常以约 60% 中性色、30% 角色主色、10% 小面积点缀作为构图起点；不是按像素硬检比例。肌肤颜色示意不限制角色肤色。强饱和色集中于眼神、饰物或少量魔法光，不能让每一块都争抢焦点。

### 5.3 光影

默认主光来自画面左上，正面略暖，阴影略冷。立绘可以有薄的反射光，但不能两侧均画厚白边。基础明暗以一层主阴影和必要的接触暗部为主；脸颊只保留少量柔和过渡。发丝、皮革与金属高光形状不同，避免整张写实厚涂或 3D 渲染质感混入。

特效层独立、可关闭。不得把永久闪白、伤害数字、血条、稀有度文字或技能名称画进角色母版。

## 6. 构图、裁切与像素密度

精确坐标见 `crop_profiles.json`。2048×3072 母版和 1024×1536 透明立绘为本轮制作规格；可交更高分辨率原稿，同时提供规定审查导出。不得将低清图片放大后宣称达到母版质量。PPI 标签不替代实际像素数。

| 用途 | 尺寸 | 本版处理 |
| --- | --- | --- |
| 完整母版 | 2048×3072 px | 头顶至脚底、手与主要道具完整；主体留出边界，背景/指南分层 |
| 立绘审查导出 | 1024×1536 px | RGBA，保留统一画布原点，不 trim |

P23 画板是 1280×856，实际界面区域是 `(0,48,1280,720)`；转换视口坐标时 `y_viewport=y_artboard−48`，上下审查标注不得导入游戏。390 px 截图只作历史布局压力证据，不批准移动端。

P24 手牌框 236×174 当前是文字优先的组件，未定义插画窗口。将半身图置入其中必须先有 P23 的 IC-21 安全区变更与 P30 的 IC-22 受理。P25 本轮提供并排裁切审查模板，不直接改 HUD。

眼睛、嘴、下巴、关键发饰、握持接点不可压在框边或状态角标下面。允许画面外延的装饰必须在清单中声明可裁区域。裁切偏移不能通过更改角色 content ID 实现；同一角色不同 variant 由 P22/P30 受理。

## 7. 敌人与 UI、特效的一致性

敌人延续相同的线条节制、二维明暗和有限材质。普通怪/精英/Boss 的区别通过轮廓、体块和主要识别物表达；不把更多发光描边当唯一等级差异。每个 phase 对应 P06 规则，不为画面效果自行增加阶段或生命值。

P27 需交命中锚点与可裁区域；锚点不能被 UI 血条、意图和数字覆盖。宽角/长武器无法放进 62×76 时，应交专用头像变体，并通过 IC-21 请求合适展示位。技术占位可继续用于 S03，但不能作为正式敌人审美通过。

P28 特效采用清楚短促的方向线、有限粒子和局部亮色；保留人物与敌人的主轮廓。采用 P23 已有的减动效/无动效规则；全屏闪白不进入本基准。特效颜色不替代“攻击/治疗/护盾/待核对”等文字。持续时间、取消、倍速与播放器契约由 P28/P29 处理，本规范不新定战斗时序。

P24 的选中、焦点、禁用原因与学习状态分区在本轮视觉审查中予以保留。任何皮肤调整均不得把“连接可用”表现成“奖励到账”。数值与动画的权威来源仍为上游业务模块。

## 8. 源文件、分层和透明导出

完整可执行要求见 `layer_export_spec.md`。接受真实可编辑的原生分层文件，附软件与版本、层树和打开证据；可另附 OpenRaster 互通副本。仅把一张合成 PNG 放入名为 PSD/KRA/ORA 的容器不构成合格分层原稿。

最低编辑能力：单独修改脸部表情、头发主色、服装主色和主要道具而不必破坏性重画整个身体；遮挡层次正确。无需为了本项目强行拆成骨骼动画部件。

导出使用无损 PNG、8-bit RGBA、sRGB 解释、未预乘 alpha；明确记录实际 ICC/sRGB 元数据是否存在。没有嵌入 profile 时记录“按 sRGB 解释，元数据缺失”，不能只靠清单自称已嵌入。浅底、深底和棋盘格只做审查合成，不烘焙进透明成品。[PNG]

## 9. 一人样本门禁

先完成一个完整角色样本：设定表、真实分层源、透明立绘、头像、横向裁切、源—导出哈希、软件版本、来源说明、自检记录和 P25 逐条评审。样本不得以本包几何指南、空白 ORA 模板或 P20 文本头像替代。

`sample_acceptance.tsv` 的硬项包括来源、可编辑性、结构、脸部一致、握持、裁切、alpha、缩略图与引用关系。硬项不得通过加权平均抵消。缺图记 BLOCKED；已看见但有缺陷记 FAIL；无运行环境的项目记 NOT_RUN。没有执行的项不能先填 PASS。

P25 可以签美术审查结果；P37 独立签来源/许可范围；P30 签实际资源导入；P35 审流程证据。单人 P25 审美通过也不自动批准 3 人总量：仍需 P01 的数量范围记录。当前 `formal_asset_register.json` 为空，`mass_production_allowed=false`。

## 11. 返工与版本纪律

每条意见有编号、base SHA-256、唯一修复 owner、可观察的关闭条件和受影响版本。画师以新版本交回，P25 对照原稿与导出复审；P25 不直接修画师源文件。连续两轮没有新增证据仍未关闭时，由 P01 仲裁质量/数量/成本。

本版文字和量尺的兼容澄清使用 0.1.x；比例体系、角色主色、窗口形状等影响已制作素材的修改必须更新风格版本、列出受影响资产并重新审查。涉及用户审美偏好或新增成本，P01 登记后提交用户，而不是默认扩大范围。
